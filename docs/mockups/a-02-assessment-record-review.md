# A案：Assessment record — visual proposal

2026-09-12。ユーザーの提出・結果待ち・再提出の記録を中心にする提案を受けたモック。作成時点は検討用だったが、その後PC版の実装方向として採用され、同日 `app/` に反映した。画像内の省略・不整合は本書と製品仕様を優先している。

## 方向
落ち着いたアイボリー、深緑、セリフ見出しのA案を継承する。課題をチェックして消すことより、提出から結果確認、必要な再提出まで同じ記録が続くことを中心に据える。

- カードに現在の状態と提出の足跡を表示する。通常は短く、展開時に各回の以前の締切・提出日時・結果を見せる。
- 結果待ちは提出日時と経過日数を示し、長い順に並べる。返却予定を推測しない。経過日数を進捗率に見せない。
- 科目ごとに、自分が登録した課題の状態を数える。学校が定める総課題数、合否、公式の科目修了率とは扱わない。
- 名前だけで追加できる入口と、未設定カード上の + Unit / + Due date を引き続き採用する。
- 学校に実際に提出する操作ではないという注意を維持する。

## 画像と実装を区別する点
- この8件のサンプルに今日締切がないため Today が描かれていない。実装仕様は Overdue / Today / Coming up / No date yet の4区分で、期限切れを最上段に置く。
- すべてのサンプルに科目があるため + Unit は画像にないが、未設定の場合に必要。
- 結果記録のポップオーバーには実装時に対象課題名を表示し、どの記録を変更しているか明確にする。
- 科目マーカーは登録課題ごとの状態の数。順序付きの必須工程や学校の課題総数を意味させない。
- Networking の色の細かな揺れは生成画像の不整合。実装時には科目色を統一する。
- 追加欄の左右のプラスと Add の重複は、そのまま採用せず操作を一本化する。
- 24件すべてに詳細履歴を常設しない。普段は要約し、必要な課題のみ展開する。
- 日付はカードから直接カレンダーを開き、直接入力と曜日を含む読み返し表示も残す。
- モックの完成例が初回画面ではない。空状態は課題名入力と、読み取り専用の見本への入口を優先する。
- Completed は学生が記録した状態。成績、合格、学校側の判定をアプリが推測しない。
- 再提出では既存記録を上書きせず、新しい回を追加する。既存の同期・競合・履歴・ごみ箱・復元の安全性を維持する。

## 次の検証
この案を実装する場合も、初見の人が説明なしに課題名だけで1件を追加できるかを先に確認する。提出済みが消えず結果待ちに移ること、再提出の過去の記録に辿れることも確認する。独自性や見た目だけで有料化の需要は判断しない。
