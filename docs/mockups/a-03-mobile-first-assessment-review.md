# A案・スマホ版：最初の入力と提出の記録

2026-09-12。a-02-assessment-record-v1.png のスマホ展開。作成時点は検討用だったが、その後スマホ版の実装方向として採用され、同日 `app/` に反映した。

## 4画面
1. ログイン後の空状態。課題名の入力欄と Add を直接置く。科目・締切は必須にしない。読み取り専用の見本と一括登録は副入口。
2. 名前だけを登録した直後。No date yet にカードが現れ、+ Unit / + Due date から後付けできる。履歴は Added と View record までに留め、初回から空の工程表を並べない。
3. 普段の一覧。Overdue → Today → Coming up → No date yet。再提出の回数と以前の提出を短く表示し、詳細は同じカードから開く。科目集計と月表示は入口に畳む。
4. 提出後。Waiting on results と Completed。経過日数は事実の記録であり、返却予定や返却率を推測しない。

## 実装時に解決すること
- このモックはログイン後。アカウント不要モードは採用済みとは扱わない。登録負担の実測は認証と課題入力を分ける。
- 入力→Add またはキーボード送信で登録する。追加後にもう一度 Save は要求しない。科目や日付の任意項目を埋める義務に見せない。
- スマホのソフトウェアキーボード表示中には入力欄と送信操作を隠さない。固定タブがキーボードと競合しないことを実機で確認する。
- 静止画では入力中のキーボード、横幅320px、文字拡大、縦スクロールは検証していない。3画面目の下端カードも固定欄で隠れず最後までスクロールできる余白が必要。
- 画像の小さいリンクをそのままタッチ領域にしない。操作領域は最低44px程度を確保し、密度より誤操作防止を優先する。
- 24件は縮小して1画面に押し込まない。同じ並びの縦リストとして表示し、件数・科目・月から辿れるようにする。
- + Due date は余分な相対日付メニューを挟まずカレンダーを直接開く。英語の日付入力と曜日を含む読み返しも検討を継続。
- Mark submitted は今日以外も利用できる。学校へ実際に送信しない注意を確認操作に残す。
- 画像内の重複した Submitted 日付表記は実装時に整理する。
- 保存失敗、未同期、競合は通常時の静止画には描いていない。成功のみ短く消し、未解決の状態は正直に表示し続ける。
- 科目単位の完了率や合否は推測しない。既存の提出履歴・ごみ箱・競合検出・復元を維持する。

## 初見評価
説明なしに、ログイン後から1件を追加するまでの時間、止まった場所、説明したくなった場所を記録する。次にカード上で科目・締切を足せるかを確認する。認証から始める場合の総時間は別に記録し、課題追加だけの時間と混同しない。
